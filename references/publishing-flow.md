# Markdown → 飞书 → 公众号发布流程

## 一、确定文章维护源

1. 找到本次要发布的最终 Markdown 或正文。
2. 若文章来自写作任务，确认写作已经完成，标题和正文不是仍在生成的中间稿。
3. 记录源文件路径或原始文档链接，以便导入异常时回查。

不要直接把 Codex 对话中的零散段落逐段粘进公众号编辑器。先形成一份完整、可复用的发布源。

## 二、建立飞书发布稿

1. 在飞书云盘的“写作”目录中新建空白文档；若用户指定了其他目录，以用户指定为准。
2. 将 Markdown 的标题和正文完整粘贴或写入飞书文档。
3. 到文末检查是否存在仅供写作研究使用的内容，例如：
   - “主要资料”；
   - 论文、报告和研究材料列表；
   - 为写作阶段保留、但不面向读者的参考链接。
4. 删除明确属于研究底稿的尾部区块。若来源说明本身是文章的一部分，保留并向用户说明，不要只按标题关键词粗暴删除。
5. 清理粘贴带来的多余空白：
   - 删除文档开头、结尾及段落之间仅含空格的空行；
   - 将连续多个空白段落压缩为正常的单段间距；
   - 删除中文字符之间明显由粘贴产生的多余空格；
   - 删除段首、段尾残留空格；
   - 保留英文单词间空格、列表缩进、引用结构以及有明确排版作用的留白。
6. 从标题滚动到结尾，确认没有缺段、重复粘贴、残留提示词、模型说明、多余空白或异常格式。

检查点：飞书文档此时应包含正确标题、完整正文和干净结尾，但暂不要求已经有图片。

## 三、设计并生成三张配图

先通读文章，确定三张图分别表现什么，而不是只复述标题。

- 题图：概括文章的核心矛盾或主场景，构图适合公众号封面裁切。
- 正文图一：对应第一个重要机制、冲突或转折。
- 正文图二：对应后半篇的重要判断、行动或结论。

默认要求：

- 横版，优先接近 16:9，建议不低于 1600×900；
- 三张图风格、色彩和人物设定一致；
- 画面简洁，有明确视觉中心；
- 不生成文字、Logo、水印或仿公众号界面；
- 不把文章中的抽象概念机械画成流程图，除非用户明确需要图解。

生成后检查三张图片是否内容重复、人物形象跳变、裁切困难或出现文字伪影。失败的单张只重做该张，不必无依据地全部重做。

## 四、把图片插入飞书文档

1. 复制或上传题图，在标题和正文开头之间插入。
2. 找到正文图一对应的段落，把光标放在该论点或场景开始前，再插入图片。
3. 用同样方式插入正文图二。
4. 重新从头到尾检查：
   - 共三张图片；
   - 图片没有连续堆叠；
   - 图片没有插进句子或列表中间；
   - 图片上下没有造成大块留白的多余空段；
   - 正文顺序未因粘贴图片而改变；
   - 文末研究资料仍然已经清除。

录屏中的基准做法是从生成结果中“复制图像”，回到飞书文档，在语义位置粘贴。若工具支持直接插图，也必须获得相同的可见结果。

检查点：只有飞书文档已经包含完整正文和全部配图，才允许进入公众号导入。

## 五、通过壹伴导入公众号

1. 使用 `ego-browser` 打开微信公众号后台 `mp.weixin.qq.com`，进入目标账号。
2. 进入草稿箱并新建图文，或进入用户指定的待编辑草稿。
3. 打开壹伴的“导入文章”。
4. 选择“飞书文档”。
5. 粘贴已经完成的飞书发布稿链接，点击“采集文章”。
6. 等待导入结束，不要在加载过程中重复点击采集。

正常流程在这里第一次、也是唯一一次导入。不要为了查看无图版本而提前导入。

## 六、导入后验收

至少核对以下项目：

- 标题与飞书发布稿一致；
- 作者来自原稿或用户已确认的署名，不凭空填写；
- 正文开头、正文中段和结尾均存在；
- 字数与源文档大致一致，没有明显截断或重复；
- 图片数量符合预期，默认应为三张；
- 文末没有“主要资料”、内部研究链接或写作提示；
- 排版没有多余空行、中文间误插空格、超大间距、错位图片或残留模板内容。

若不通过：

1. 判断问题来自飞书源文档还是壹伴导入。
2. 源文档有误时，回飞书修复后再重试导入。
3. 外部写入结果不明时，先检查当前草稿，避免重复生成多个相同草稿。
4. 没有新证据时停止重复点击，向用户说明具体阻塞。

## 七、封面和发布前检查

1. 从三张图片中选择构图最适合横向裁切、主体清晰的一张作为封面；通常优先题图，但不固定使用第几张。
2. 打开封面编辑，检查裁切后主体、面部和关键物件没有被切掉。
3. 再检查标题、署名、正文、三张图片、封面和文末。
4. 如用户只要求准备草稿，保存草稿并在此停止。

## 八、正式发布

1. 所有准备和检查完成后，展示当前状态和即将发布的文章标题。
2. 在点击“发布”之前请求用户确认。不要提前请求，也不要把此前笼统的“帮我发”替代动作发生时的确认。
3. 用户确认后点击“发布”。
4. 出现微信验证二维码时，将控制权交给用户扫码。
5. 用户完成扫码后，检查公众号后台、发布记录或成功页面。

状态判定：

- 编辑器内容完整：草稿已准备；
- 二维码已出现：等待扫码；
- 用户说已扫码但后台未确认：发布结果待核实；
- 后台或发布记录显示文章：已核实发布成功。

不要仅凭点击了按钮、出现二维码或用户完成扫码就直接宣称发布成功。
